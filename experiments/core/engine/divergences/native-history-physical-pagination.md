Native recorded-row restoration needs bounded all-version history, unlike the
pinned ordinary snapshot reader. Keep the same five tables and existing keys.
Extend the ordered prefix/digest secondary with timestamp, a historical form the
pin already tolerates. Replace it through explicit data-preserving platform
maintenance; logical app installation does not perform this DDL.

Select B physical tuples before time eligibility, charge all actual work and
hydrate only eligible exact revisions. Preserve the actual exclusive tuple cursor,
including out-of-window positions. This prevents both unbounded duplicate-group
ordering and hidden filtering across time-ineligible keys. Add no history table,
read transaction, fallback engine, synthetic cursor or second authority.

Use this difference only while the native history contract requires it. Retirement
requires another independently challenged bounded mechanism and installed-target
disposition, not merely removal of its index. Real PostgreSQL plans and complete
upgrade/reader proofs remain gates; no performance improvement is yet established.
