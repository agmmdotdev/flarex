# Fresh admission cost and observer calibration

The [traced full run](./traced/manifest.json) and [untraced full run](./untraced/manifest.json) each contain 104/104 successful ordinary-role PostgreSQL samples of the same four private workloads: three warmups, 20 measured warm requests and three cold requests per workload. Each directory retains a byte-preserved report, deterministic gzip of the raw record, a 104-row sample index, an exclusion record and source/file hashes. The original [optimized series](../optimized/manifest.json) remains separate.

| --- | ---: | ---: | ---: | ---: | ---: |
| Application + Product | 3,020.2 ms | 2,337.0 ms | 2,341.4 ms | 2,231.5 ms | 3,842 / 97 |

| Standalone finite workflow | 362.1 ms | 332.4 ms | 333.0 ms | 344.6 ms | 480 / 6 |

The optimized and candidate **request spans** use the same traced observer contract. The candidate physical search proof still reads current PostgreSQL catalog state with every predicate intact; its OID-anchored query avoids the former join planner cost. The logical working set avoids an empty admission transaction immediately before a checked read while keeping the fresh check inside the read transaction and state-only guards. No selected dependency, authority, publication or settlement check was removed. The candidate mixed workflow's warm median physical proof falls from 248 dispatches and 3,143.2 ms summed driver await to 224 dispatches and 286.4 ms. This is driver await, not server time or an additive request phase.

The two candidate series ran **sequentially**, traced first. Their outer invocation wall medians differ by about 4.7% for Product, 3.8% for Product plus Payload, 0.1% for the mixed workflow, and in the opposite direction by about 3.5% for standalone. System state, cache and scheduling drift were not randomized away; these are descriptive differences, not isolated causal estimates of observer overhead. The untraced run installed no SQL/phase observer, so its trace span, SQL awaits, dispatches, transaction counts and trace coverage are **unavailable**, not zero. No untraced historical optimized baseline exists, so the untraced candidate cannot establish an untraced before/after speedup. The same fresh Worker lifecycle, request boundaries, business assertions, publication check and retained inventory applied in both candidate modes.

The full runs still exceed the proposed 100 / 200 / 500 ms warm mixed workload p50 goals in the [low latency preflight](../../../../../roadmaps/mixed-mutation-core/06-low-latency-execution-preflight.md). The next measurement-led direction is bounded, same-short-transaction reuse of already verified Application selected evidence and fewer selected metadata awaits. It requires an explicit proof of first-failure order and callback lifetime; no cross-transaction cache, physical-certificate path or changed trust boundary is authorized by these measurements. Neither series measures hosted Cloudflare transport, native ORM parity or production capacity.
