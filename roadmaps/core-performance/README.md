## Decisions And Working Loop

The latest owner direction replaces an automatic full end-to-end measurement
after every small performance iteration with this loop:

1. Select one bounded component outcome and inventory its real owners, callers,
   proof cuts and resource limits. Record the focused decision before changes.
2. Establish a component baseline using real operations. Report pre-existing
   host/catalog/entry/authentication setup separately, without omitting it from
   total-work accounting or claiming a different execution profile is equivalent.
3. Attribute observed work and choose one actual owner optimization. Preserve
   required proof and refusal order; do not prescribe a cheaper guard from a
   phase total alone.
4. Implement through that owner, migrate affected consumers and remove displaced
   paths. Run focused correctness tests, affected type/source checks, lint and
   both project reviews on the final scope.
5. Compare component traced structure and quiet untraced distributions under
   declared identical settings and construction/demand policy. State whether
   labels describe first/successive demands or cold/warm construction; do not
   infer host amortization. Keep all samples, retries, failures and outliers
   explicit. Reconcile any failed gate.
6. Commit the coherent iteration after validation and cleanup. Full mixed
   traced/untraced measurement is an integration gate at declared group milestones,
   cross-component or lifecycle contract changes, and whole-goal acceptance.
   An owner improvement, including immutable compilation with unchanged SQL,
   does not automatically trigger the full graph benchmark. Bounded connected
   consumer correctness remains required in each iteration.
