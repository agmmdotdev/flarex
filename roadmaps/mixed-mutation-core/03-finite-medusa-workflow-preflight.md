# Finite Medusa workflow in the private mixed attempt

Status: **implemented and validated as a finite private runtime profile in isolated scopes.** The [Application/Product](./01-application-product-attempt-preflight.md) and [Payload Local API](./02-payload-local-api-attempt-preflight.md) slices are also implemented only in isolated scopes. This third package extends their one journal-backed root; it does not activate a named environment or expose an authoring API. The [mixed execution design](../../design-notes/flarexdb-mixed-mutation-execution.md), [accepted database design](../../design-notes/flarex-db-accepted-design.md) and [mixed roadmap](./README.md) govern authority and completion.

The replacement uses the semantic `flarex.session-journal` persisted format with
ordered `AdmittedParticipantOperation` source contributions. Request, outcome
and write-event bytes use exact codec 2. [Migration 0118](../../packages/persistence-postgres/drizzle/0118_admitted_operation_journal.sql)
changes the physical constraints only after refusing any existing session,
journal, receipt or write-event rows; named data and outstanding attempts need
an explicit disposition before activation. Application-only and direct
Product/Payload callers use the same journal format, and displaced single-source
runtime readers and issuers were removed in this coherent slice.

## Coherent outcome and exact selected graph

Run one private catalogue-launch mutation through the existing real sandbox, executor and trusted host. Seed a Product with option `Size` and value `0`, and an **already attached** Product Tag with value `preview`. The root creates an Application `productLaunch`, uses the admitted native Product title/handle/status update and selected Payload `posts` create, nested update/read and outer update/read, and uses their returned values in a dependent Application patch. Inside that same root, invoke one ordered parent Medusa workflow with two genuine `runAsStep` children:

1. The [selected `productVariantPricingWorkflow`](../../packages/medusa-adapter/src/product-variant-pricing-workflow.ts) creates **one** Product Variant with `Size: "0"`, **one** PriceSet with **one USD base Price**, and the stored Variant–PriceSet Link. Its real native `createProductVariantsStep`, `createPriceSetsStep`, `createVariantPricingLinkStep` and `useQueryGraphStep` remain the business operations. Read pending Variant, PriceSet, Price, PriceRule and Link graph results. The base Price has no price rules in this fixture; the PriceRule read must return an empty collection with correct pending graph semantics. This selected Flarex-authored native-step composition is **not** the full upstream Product or variant workflow.
2. The exact promoted [native `updateProductTagsWorkflow`](../../packages/medusa-core-flows/src/product/workflows/update-product-tags.ts) selects the preattached tag by ID and changes `preview` to `launched`. Read `Product.tags` within the same pending view after this child. Its native update step, hook location and workflow event remain intact. Register **no hook callback** for this profile: the native hook point exists, but no arbitrary or user callback is admitted.

The parent is an ordered definition with one immutable revision and explicit child identities, input/output codecs, method/query permissions, hook selection and event policy. Register Product **once** with `createProductVariants`, `listProductTags`, `updateProductTags` and its graph; Pricing with `createPriceSets`; Link with `create`. The Product graph permits `id`, `title`, `tags.id` and `tags.value`; Pricing and Link reads use their separate graph roots, with no invented cross-module hydration. The parent contributes Product, Pricing and Link source effects to **one** existing root outcome, alongside Application and Payload. The first child alone produces module events but no external workflow event; the tag child supplies a real native child frame and a checked `product-tag.updated` workflow event without adding a fourth source. Expect one ordered transcript and one commit's Application, Payload, Product/Pricing/Link rows, retained result, module event intents and native workflow event intent. Late failure after either child leaves no committed business rows or event intents.

The [existing pricing test](../../packages/medusa-adapter/test/logical-product-variant-pricing-workflow.test.ts) proves the selected standalone graph over logical storage, including stored Links, pending graph reads, event cardinality and generated IDs. The [tag composition test](../../packages/medusa-adapter/test/product-tag-composition.test.ts) proves native child frames, hooks/events and sticky refusal under the independently settling host. Neither proves that `host.run` can execute within a mixed attempt. The pinned [upstream `createProductsWorkflow`](../../third_party/medusa/upstream/packages/core/core-flows/src/product/workflows/create-products.ts) and [createProductVariantsWorkflow](../../third_party/medusa/upstream/packages/core/core-flows/src/product/workflows/create-product-variants.ts) still transitively select broader Link/Inventory work even when caller inputs look narrow. This package deliberately selects the already exercised Pricing branch and the exact tag update instead of claiming full upstream Product admission.

## Why this package now and boundaries

The implemented Product/Payload root already has snapshot-plus-pending evaluation, ordered durable receipts, whole-root retry and one settlement. The gap this package addressed was proving that a finite native workflow could borrow that authority across **several** genuine logical sources, expose its own intermediate graph results, and record both event families without its own commit. At this package's starting point, the [workflow host](../../packages/medusa-adapter/src/workflow/host.ts) called an independently settling `host.run`, while the [journal operation](../../packages/persistence-postgres/src/sessionJournalStore.ts) authenticated one source binding and one source's effects per syscall. Calling that standalone workflow host inside the root would create a second settlement; making each child a recursive journal syscall while the outer invocation marker is live would violate the root's in-flight/replay contract.

The admission is one fixed, sequential, database-only parent and its two named children. No full Product/Inventory workflow, generic WorkflowManager or LocalWorkflow scheduler, parallel steps, waits, remote effects, resource locks, arbitrary hooks, text/`q`/JSON search, price calculation, public APIs, hosted activation or performance optimization is included. In particular, creating a base Price and Link does **not** prove a calculated price read. Unsupported steps, callbacks, queries and event names fail closed before effects or poison the root if discovered during a child.

The existing [borrowed Commerce](../../packages/persistence-postgres/src/commerceTransaction/borrowedLogicalAttempt.ts) and [borrowed Payload](../../packages/persistence-postgres/src/cmsTransaction/borrowedLogicalAttempt.ts) evaluators construct a disposable working set for one admitted invocation. The new shared-root evaluator must preserve their checked historical reads, framework request lifetimes, native error order and per-source validation while joining pending state and usage at the actual journal owner. Framework adapters still cannot obtain raw SQL, a finalizer, commit facts or source-clock authority. No SQL transaction is held over a workflow callback.

This finite parent pins a 30-second borrowed command deadline through the existing trusted logical atomic command range (10–30 seconds) and a 256-call budget for its two children under the existing shared 4,096-call ceiling. Both selections are part of its trusted profile revision. The ordinary framework default remains 10 seconds, the selected standalone pricing child remains at 128 calls, and the root's existing 60-second attempt lease and shared ceilings remain unchanged. Each checked read still verifies every admitted source head. Common activation and readiness projections may be reused within that one short read transaction, never cached across transactions or substituted for source checks.

The first admitted mixed workflow input is **exactly** one Variant, one PriceSet, one USD base Price, zero PriceRules and one Link. Enforce that bound at admission; do not inherit the selected [standalone Pricing input/output bounds](../../packages/medusa-adapter/src/product-variant-pricing-workflow.ts) of up to four Variants/PriceSets, eight Prices/Rules and four Links. Those larger standalone inputs remain supported by their independent profile. The mixed root retains its existing deadline and aggregate graph, row, event, receipt-byte, work-call and time ceilings; fail closed on overrun, without raising shared ceilings. ## Replay, conflicts and recovery

- Generated native IDs and time values are provisional **per attempt**. An authenticated duplicate transport call returns the exact recorded operation result; a confirmed committed replay returns the exact retained root result without regenerating IDs, time, steps, hooks or events. A logical OCC restart discards the entire attempt and reruns the whole sandbox and parent with fresh frames, IDs and time; all dependent Application/Payload references must be recomputed from the new outputs. Caller-supplied stable IDs remain exact inputs and retain normal conflict/uniqueness behavior. No generic determinism engine or precommit external publication is introduced.
- A live invocation marker rejects/waits for duplicate execution. After expiry the existing execution claim and attempt lease decide abandonment, with fresh whole-root retry only after exact outcome resolution. A failed child or event/graph validation makes the root rollback-only even if native code catches the error. Cancellation joins/cuts off owned callbacks, closes the borrowed context and reports an actually committed result if it raced with settlement.
- A lost or ambiguous COMMIT acknowledgement resolves journal, commit and retained-result evidence **before** any callback rerun. Finish-only recovery verifies the same workflow revision, ordered source bindings, frame identities, receipt hashes, dependency/effect/event correlation and committed output. A binding/activation change refuses rather than silently switching the admitted graph during retry or recovery.
- Transaction-covered native compensators do not run to undo provisional database work that the root rolls back. A required compensator for an external effect would make that step unsupported here. No independent child retry or compensation transaction is admitted.

## Breaking contracts, durable data and cleanup

At this package's starting point, the journal bound one source per admitted operation: it hashed one participant, method, source and binding head, then stored that source's flat effects. The [journal schema](../../packages/persistence-postgres/src/schema.ts) checked `journal_format = 'flarex.session-journal-v2'`; this literal was **migration evidence for the existing stored bytes**, not the proposed type name. The receipt primary key has one row per syscall sequence and normalization disallowed duplicate participant-operation sequences, so several operations could not represent one outer workflow invocation. The replacement needs one aggregate operation with ordered source contributions, an exact distinct persisted journal format, syscall request/outcome codecs, receipt binding/correlation, canonical seal and commit plan. The opaque receipt bytes and write-event bytes/ordinal columns may hold that evidence without new tables, but the format CHECK **must change through a structural migration**. Receipt request/outcome codec columns also constrain the current byte shapes, and write events constrain their event codec: assign distinct exact codec identifiers to changed bytes and migrate matching CHECKs and every reader together. Include **Application-only** journal roots, codecs and fixtures with empty contribution sets, alongside Product/Payload roots; there is no mixed-only reader to retire in isolation. Audit session admission, `operation_invoking` marker and receipt, pending point/write-event children, canonical seal/decoder, executor host/syscall transport and stored-attempt authentication, Application session finish and retained outcome, point commit validation, retry/replacement and finish-only recovery. Do not guess that a type change alone is enough or add speculative new columns.

The named-environment inventory must include `fx_system_tx_session`, `fx_system_tx_journal`, receipts, point/index/relation/write-event children, execution claims, idempotency, commit facts, result and event intents, plus outstanding attempts and all readers/writers. No named environment has been audited or activated for this private profile; the presence of old-format rows there is **unknown**. **For the private replacement proof, use a fresh isolated database/schema with no old-format journal rows and the new format/codec constraints.** An existing database carrying old-format rows fails that migration precondition; merely finishing active attempts is insufficient if sealed journals or outcomes remain. Before named activation, inventory actual data and choose an explicit drain plus retained-data disposition, or a separately scoped offline conversion that preserves recovery and durable outcomes, plus named source upgrades (including Payload's index/digest change). Atomic schema/code rollout must reject old-format rows until that disposition is proven. No parallel runtime reader or silent reset is proposed. A material named-data migration decision returns to focused scope agreement before implementing that decision.

**Naming and retirement:** New code, types and APIs use plain semantic names such as `SessionJournal`, `AdmittedParticipantOperation` and `SourceContribution`. An immutable persisted format still needs an exact distinct discriminator and codec identifiers; those are data contracts, not suffixes for the current implementation. Migrate all Application and framework consumers and delete displaced single-source journal codecs, readers, issuers, exports and obsolete fixtures in this same slice. Do not first wrap or rename the displaced code only to remove it. Introduce a `Legacy...` implementation only if the named-data audit identifies a concrete unmigrated consumer or recovery obligation, with its removal gate recorded before retaining it; old stored bytes alone do not justify a speculative second runtime path.

| Existing path | Disposition in this package |
| --- | --- |
| Application-only and direct mixed Product/Payload single-source envelope, codecs and singular issuer/commit assembly | **Replace** with the general ordered envelope; migrate all affected callers and tests, then delete displaced readers, issuers, exports, codecs and obsolete fixtures in the same slice. |
| Standalone Medusa atomic workflow `host.run` | **Retain** for current independently committed workflow callers; it remains a distinct supported execution profile, with the existing SDK runner and resource/event mechanics shared where possible. Reassess retirement only after named callers migrate. |
| Native selected services, steps, graph and tag workflow | **Retain/extend** via narrow trusted borrowed bindings; do not copy their business logic into the journal or weaken source-preservation guards. |
| Journal point overlay, working-set historical readers, scope-clock publication and committed recovery | **Extend** the multi-source evidence and current readers needed here, migrating all affected callers and removing displaced single-source paths. Keep their one-authority semantics. |
| Possible old-format named roots and outcomes | **Inventory conditionally.** If present, preserve their exact data and recovery meaning through an approved drain or offline conversion; do not keep a legacy runtime without a named consumer and removal gate. |

## Decisions for focused scope agreement

1. Admit the fixed two-child parent described above with exact Product/Pricing/Link calls, one Variant/PriceSet/USD base Price/Link, empty native tag-hook registration, selected graph reads and both checked event families. Keep unsupported steps and broader upstream graphs closed.
2. Use one outer invocation marker and aggregate receipt with ordered, individually authenticated source contributions. Give changed request/outcome/event bytes distinct exact format identifiers, update coherent physical constraints and all Application/framework/recovery readers, then delete displaced single-source runtime paths. Retain the journal as the only durable pending overlay and settlement owner.
3. Add one trusted `medusa.workflow` selector to the executor's bounded set of three selectors, bound to exactly Product, Pricing and Link source definitions; the root then has four framework sources including Payload. No synthetic merged source or caller-configured registry.
4. Prove the replacement in a fresh isolated database with no old-format journal rows and fail closed on existing old-format data. Named-environment cutover awaits an inventory and explicit retained-data/outstanding-attempt decision. Keep current finite deadlines and aggregate budgets, refusing overrun without increasing ceilings.

## Validation and exit gate

First prove a neutral three-source fixture through the same replacement core path, then the real connected Worker mutation with Application, native Product, Payload Local API, the two SDK child frames, Pricing and Link methods, pending graph/`Product.tags` reads, dependent Application patch, exact root output and one commit's module and workflow event intents. Verify that the `Size: "0"` option permits the Variant, the tagged Product relationship existed before update, and the stored Link joins exactly the returned Variant/PriceSet. Check empty PriceRules rather than implying rule creation or calculated pricing. Reject wrong workflow revision, scope, source head, principal, method, graph field, event name/group, child order, hook registration and forged/duplicate/omitted contribution before settlement.

Exercise late failure after both children and after Payload work, caught child refusal, rollback-only, transport duplicate while invoking and after receipt, whole-attempt conflict retry with fresh IDs/frames and dependent references, cancellation while a child is pending, snapshot expiry, finish-only recovery and lost COMMIT acknowledgement with no committed callback/event replay. Audit selected point, unique, relation and indexed historical reads against concurrent **standalone** Product/Pricing/Link/Payload/Application writers. In particular, native Variant creation reads Product options/values and existing variant combinations: race an option-value removal or duplicate `Size: "0"` combination. Race a standalone Link create for the same Variant–PriceSet pair; the stored rich Link's active-pair unique claim matters, while endpoint FK protection must not be assumed. Race the tag's point value change or another tag claiming `launched` under its active unique index; check `Product.tags` relation-membership change where an admitted standalone writer can make it. Use explicit IDs for controlled conflicts and a generated-ID case for replay. Verify same-scope lock order and no transaction across callbacks. `q`, text/JSON search and resource locks remain rejected, so they need no invented historical-search or lease proof in this package.

Run focused native, neutral core, protocol/journal/commit, executor/Worker and three-consumer tests on PGlite and an ordinary-role real PostgreSQL lane with distinct connections; keep their claims separate. Run affected typechecks/builds, pinned-source/provenance guards, `pnpm lint:core`, `pnpm lint:diff`, exact staged diff lint, and both standing diff reviewers, rerunning after substantive fixes. Inspect actual persistent schema/DDL before declaring the format migration complete. Migrate affected callers, remove displaced single-source internals/tests/exports/docs and make one scoped commit only after the connected proof is green. Private correctness does not establish arbitrary workflows, hosted scale, production activation, calculated prices or public APIs. Measurement and optimization remain the next package.
