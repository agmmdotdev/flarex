## Selected Contract

### One Root And Explicit Framework Bindings

Application owns the logical attempt, snapshot, pending state, dependencies,
budgets, cancellation and final outcome. Medusa services/finite workflows and
Payload Local API operations borrow that root through their actual bindings.
They retain native access, validation, projection, hooks, results and events.
No participant starts a direct host or independently settles as a fallback.

Keep one root evaluator. Local pending-only work stays tentative and uses its
local lifetime and budget checks. No SQL spans Application execution, getters,
native callbacks requesting more work, external effects or workflow suspension.
Later dependent native reads derive a new bounded demand from owned results;
do not guess future callback behavior in advance.

### Query-Required Intermediate Readiness

The existing trusted query/compiler owner derives a bounded read requirement
from the captured input and authenticated schema:

- Point and multi-point access: exact identities, row/history storage and visibility.
- Ordered/unique access: selected definition, canonical predicate/key, ordering,
  page and missing-membership evidence, coverage and physical access path.
- Relations/population: actual traversal edges, target visibility and dependent
  keys derived from owned rows. Additional dynamic demand is checked when known.
- Reference/delete checks: required target or reverse paths. Full mutation
  maintenance and final constraints remain complete.

Bind the requirement to its issuing preparation, source/schema, attempt/root and
bounded lifetime. A method name, source tag, digest or caller-provided table/index
list cannot establish completeness. A read requirement cannot satisfy full-entry,
seal, publication or migration consumers.

This deliberately changes source-wide intermediate refusal: after successful
full entry, an unused same-source index becoming unavailable may allow a tentative
scalar read to continue. A demanded index, relation target, physical definition
or coverage failure still refuses before using it. Full seal/publication still
refuses unrelated source damage before durable success. Unsupported query forms
fail admission rather than falling back to current-state reads.

### Fresh Authority And Managed Integrity

Preserve fresh scope/placement, principal/method, session/lease/journal/claim,
attempt fence, storage generation, revocation, source/head pins, snapshot retention,
post-lock database time and deadline checks at actual database access. Preserve
lock order, refusal order and the protected tail. Body or tail refusal poisons the
root even if native code catches the boundary error. No live verdict crosses SQL
transactions through a cache.

Preserve established local capability, lifetime and budget refusal before foreign
input capture. Capture and normalize query inputs outside SQL; check fresh exact
authority before readiness or data access, then the protected tail after the body.
Changing the proof selection must not reorder the first observable failure.

Adopt the existing managed installation owner only after the handoff establishes
its finite-user coverage. Inventory how the actual credential, database/namespaces,
incarnation and structural generation reach every accepting transaction and how
all affected reads/writes/recovery/build users interlock with maintenance. Test
pool/reconnect, restore, maintenance crash/drain and predecessor fencing. Keep
the actual metadata invalidation/epoch guards until their writers have proved
replacements. A matching epoch or pool object alone is not installation integrity.

Authenticate immutable query/schema metadata under the existing bounded host
owner, with miss, capacity, eviction, invalidation and close/drain behavior. Query
requirements must be accessible without rebuilding or enumerating the whole source
on a warm read. Demand-specific preparation, incremental retention and transfer
follow the requirement. A justified complete immutable catalog, full root entry,
final verification and installation inventory may retain source-wide cost under
their own bounded lifetimes; report that cost separately and in the complete
request or actual amortization interval. Cold preparation remains charged; moving
full structural verification to every cold Worker is not this replacement.

An uncovered managed caller/writer is a concrete completion blocker. Retaining
full catalog attestation for the selected finite graph is not full delivery of
this package. Distinct unmigrated direct/durable profiles retain their named
contracts and regression obligations; they do not become silent fallback paths.

### Relevant Pending State And Bounded Storage Work

Select pending Application seeds from the trusted demand. Exact point reads can
select exact identities. Predicate/range/page/relation demand must account for
inserts, updates, moves and deletes entering or leaving membership. Filtering only
the pending value is insufficient when the original row matched the query.

Where authenticated evidence cannot prove exclusion, conservatively include the
queried table's relevant bounded seed set. Do not include every table in the
framework source. Authenticate each included seed's original snapshot observation
before it influences membership, order, pagination or constraints. Group required
historical identities by table within the checked frontier, preserving observation,
failure and resource-charge order; do not perform full root admission per seed.

Use existing relational/query compilers, working-set grouping and row decoders.
Batch compatible already captured root selection, hydration and relation work.
Keep native normalization and genuinely dependent calls at their native boundaries.
Do not add an adapter cache, second query interpreter or another pending-state owner.

## Cost Contract And Acceptance

Measure a fixed existing native demand and its real borrowed counterpart with
matching inputs, selected data, branch, visibility, complete result and errors.
Record the exact prepared lifetime and initial root/setup work separately while
including every actual fresh check and miss in the interval it belongs to.
Native Medusa alone is not a complete reference for the whole mixed graph.

Before changing the mechanism, record the matched baseline and a small additive
warm median/P95 read-overhead budget in this preflight, along with graph-derived
transaction, sequential round-trip, server-work, metadata-row/byte and hydration
bounds. Numerical read budgets remain to be fixed against that exact workload;
the standalone 2/5 ms overhead target is a reference, not an automatically adopted
mixed threshold. Do not substitute the old standalone 400 ms guardrail.

Keep the existing complete mixed p50/P95 goals: Product 100/200 ms,
Product + Payload 200/400 ms, finite mixed workflow 500/1,000 ms. They are targets,
not forecasts or achieved native parity. A package can pass its declared local
budget while those whole-goal gates remain open; report the measured remaining
gap and owner instead of calling the overall redesign complete.

Mandatory structural and scaling gates:

- Holding real demand fixed, grow unrelated tables, indexes and relationships
  within the same source and connected sources. Warm selected-read proof,
  demand-specific metadata transfer and incremental retained preparation must
  follow the requirement, not source breadth. Separately report complete catalog,
  root-entry, final and installation costs without excluding them from full-request
  or supported-lifetime totals. Count server work hidden inside functions and triggers.
- Vary actual rows, selected edges, pending seeds and native calls independently.
  State the expected bounded growth for required work and retain all outliers.
  No full authority transaction per row or seed is accepted without a concrete
  semantic obligation.
- Include cold/miss/reconnect, same-scope contention, independent scopes and
  invalidation/reprepare. Installation/setup cost stays visible and amortization
  uses an actual supported lifetime, not an assumed permanent Worker.
- Keep SQL dispatches, protocol submissions and network round trips distinct.
  Measure complete latency and observed server/CPU/bytes separately; overlapping
  phase intervals cannot be added into a causal latency explanation.

Complete one real Worker/Application + native Product + actual Payload + finite
workflow measurement milestone after this shared lifecycle change. Fewer SQL
submissions or passing helper tests alone cannot accept the package.

## Correctness, Cleanup And Delivery

Use PGlite for fast semantic coverage and ordinary-role real PostgreSQL with
distinct connections for transaction, isolation, locking, maintenance and races.
Exercise the actual native/Local API/Worker boundaries. Required witnesses include:

- Exact point absence/tombstone, predicate/range/page/unique membership and
  snapshot-plus-pending interleaving; standalone writers retain conflict evidence.
- Pending rows entering/leaving a result, deletes and sort changes, relation
  visibility, relevant original-snapshot hydration and conservative exclusion.
- Used-definition failure versus unused-definition tentative success followed by
  full-final refusal; read requirements cannot authorize full admission.
- Wrong source/schema/root/lifetime, forged requirements and unexpected installation.
- Invalid capability combined with a foreign getter failure preserves local-guard
  refusal first; valid input capture remains outside SQL and precedes data access.
- Revocation, head, fence, expiry, placement, protection and maintenance changes;
  caught storage refusal remains root-aborting with original first failure.
- Native full DTO/error, access/hook/event order, operation-close constraints,
  cancellation and whole-attempt conflict retry.

Remove displaced finite source-wide intermediate read assembly, eager unrelated
seed hydration and duplicate construction in the same slice. Preserve meaningful
assertions under the replacement and remove obsolete exports/fixtures. Retain an
old route only for a named unmigrated profile or durable obligation with an exact
removal gate; do not retain a second healthy engine for the selected graph.

Complete affected typechecks/builds, source/compatibility guards, core/diff/staged
lint, both project reviews and substantive-fix reruns. Root coordinates and owns
Git; assigned workers edit disjoint paths and reviewers remain read-only. Stop
owned temporary runtimes. Commit only the complete verified slice and reconcile
these status labels without adding test receipts or checkpoint logs to roadmaps.
