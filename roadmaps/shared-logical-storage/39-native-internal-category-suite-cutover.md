# Native Internal Category Suite Cutover

Status: implemented under the shared-storage completion goal.

The broader retained physical Product runner still has three existing
statement-budget failures in Product update cases. Rerunning those cases with
the pre-cutover test entry and configuration reproduces the same failures;
they do not belong to this internal Category execution path.

## Connected Outcome

Run the pinned ProductCategoryService list, retrieve, count, create, update and
delete cases against one admitted logical Product source. The 31 original test
bodies exercise parent/descendant trees, rank and path maintenance, failure
semantics and selection. Their current runner installs a deployment-named
physical Product profile even though the three private Category boundary checks
and the Category/Currency atomic proof already use generic storage.

The accepted shared-storage design makes the native service and Product adapter
the Category semantic owner; Flarex owns scoped logical rows, indexed selection,
transaction settlement and publication. Reuse the existing internal Category
commands and exact silent logical receipt. This is a runtime consumer cutover,
not a claim that a small test catalog proves high-row Category query capacity.

## Replacement And Scope

Replace the pinned suite's physical `@medusajs/test-utils` runner binding with a
focused logical Product host. Keep the upstream test bodies and their admitted
coverage reporter. Remove this suite from the broad physical Product entry and
its coverage list; that runner remains for its named public Category and other
unported Product cases. The focused runner supplies only the six native
ProductCategoryService methods and refuses unadmitted methods or caller-owned
contexts. Between test cases, delete Category leaves before ancestors through
the same admitted logical command, without raw test SQL or a second settlement
path. Retain history and other-source definitions; only per-case rows reset.

This breaks a private test fixture/alias and physical installation dependency.
It changes no public Medusa API, durable identity or named data. Do not add a
physical fallback, weaken the original assertions, or keep a duplicate
physical execution of these 31 cases. Product physical storage still has named
unported consumers and its separate removal gate.

## Validation And Completion

All admitted pinned cases must execute on PGlite and ordinary-role PostgreSQL
with their exact original assertions. Add a direct two-shop or unrelated-row
regression if native cases do not witness confinement or bounded selection.
Preserve the preceding logical Category receipt tests, source promotion guard,
typechecks and affected lint. Run both required read-only reviews on the final
diff. Remove displaced runner imports, coverage registration and fixture code
in the same scoped commit. If a native case exposes a shared-owner defect,
record its failing witness and correct that owner under the standing approval;
do not filter it in the adapter.
