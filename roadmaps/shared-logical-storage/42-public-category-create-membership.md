# Public Category creation with Product membership

Status: selected under the shared-storage completion goal.

## Connected outcome and owner

Make native public Category creation on the generic Product source accept its
declared Product memberships and rank shifts, with exact tree, pivot and event
receipts. This is the missing composition needed by every case in the pinned
21-case `ProductModuleService` Category suite: its setup creates native Products
and Categories carrying inverse Product links. The preceding indexed ancestry
correction removes a whole-catalog admission limit but does not prove these
public writes.

Medusa retains handle/rank/path normalization and module messages. Flarex owns
the scoped row/index/pivot/FK writes, one transaction, ordered facts, event
admission and recovery. Reuse the existing internal Category mutation validator
for tree behavior; separately bind public requested Product IDs to every pivot
and Category messages to every root or sibling transition. Do not add a second
tree algorithm, physical fallback, SQL writer or transaction owner.

## Replacement and compatibility

Replace the public create receipt that accepted only a single Category row.
The private policy must admit native scalar or array results, optional native
handle generation, Product membership inserts and sibling rank maintenance,
while rejecting any unrelated row, pivot or event. The native public API and
durable identities do not change. Existing logical Category creation callers
use the strengthened receipt; no dual validator is retained.

The full public Category suite remains physical until its public update/delete
receipts and focused logical runner move with all 21 unchanged assertions.
The separate physical-only Category boundary tests contain generated-table
SQL injection and physical inventory assertions; replace their isolation,
rollback/replay and fact witnesses on generic storage before retiring them.
These are named temporary consumers, not the destination. Product physical
table removal still needs all other consumers and an approved data disposition.

## Proof and finish gate

Use native Product creation, then create Categories with requested Products and
a rank shift on the same logical source. Prove inverse Product projection,
native created/updated event ordering, idempotent replay and atomic missing-
Product refusal on PGlite and ordinary-role PostgreSQL. Preserve direct
Category/Currency and internal Category regressions. Run affected typechecks,
source guards, lint and both required read-only reviews. Record the remaining
21-case public suite and physical-boundary retirement gates without presenting
this selected creation path as full Category parity or broad scale proof.
