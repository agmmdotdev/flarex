# Native public Category suite on logical Product storage

Status: selected under the shared-storage completion goal.

## Connected outcome

Move all 21 unchanged pinned `ProductModuleService` Category cases from the
physical Product runner to one generic logical Product source. They create
native Products and Categories with inverse memberships, then exercise public
tree reads, count/retrieve, creation, update and leaf deletion. The preceding
creation slice authenticates Product pivots and sibling-rank events; update and
delete still need public logical receipts before the suite can move.

## Owner, alternatives and breaking change

Medusa remains the owner of handle normalization, sibling rank/path changes,
serialization and module messages. Flarex remains the single scoped row,
relationship, index, transaction, fact, event and recovery authority. Adapt
public command inputs/results to the existing internal Category tree validator;
authenticate Product pivot deletion and native created/updated/deleted messages
separately. Do not duplicate the tree algorithm, rely on a capped physical
catalog, split a native call across transactions, or introduce SQL access in
the runner. A core query or FK gap exposed by the native suite belongs to its
shared owner under the standing approval.

Replace the private test-runner alias, physical fixture assumptions and the
broad runner's duplicate Category registration. The unchanged native public
assertions, DTOs, event semantics and durable identities stay authoritative.
No dual path remains for this suite. Reset between cases through admitted
logical deletes in dependency order; preserve schema and history. The separate
physical-only Category boundary tests inject generated-table SQL failures and
inspect physical table inventories, so retain them as a named consumer until
equivalent generic-storage isolation, rollback, replay and fact witnesses
replace them. Other Product methods also retain the physical runner. Physical
table removal still requires their cutovers and approved data disposition.

## Finish gate

All 21 original cases run with unchanged assertions on PGlite and ordinary-
role PostgreSQL. The focused runner proves Product setup, inverse population,
tree mutations, exact event receipts, per-case cleanup and refusal for missing
targets. Add direct forged-pivot/event and replay witnesses where the native
suite lacks them. Preserve the 31-case native internal Category suite and the
logical Product/Category creation and Category/Currency composition tests.
Run source guards, affected typechecks/lint and both required read-only
reviews. Large sibling groups, arbitrary-depth trees and hot-shop throughput
remain separate measured capacity gates.
